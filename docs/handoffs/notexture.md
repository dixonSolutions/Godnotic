# Missing map textures: investigation

The screenshot's map, server, installed data set, GPU and console log are not available here. The checkerboard is consistent with the engine's missing-texture image; its specific cause on that device is unverified.

The staged Android zip excludes xonotic-maps, xonotic-music and xonotic-nexcompat; it removes textures, maps and other media from xonotic-data, then adds a small menu boot subset. Android's DataSession waits for the manifest's first_play packs, then DataService fetches the rest subject to unmetered network or the user's mobile-data consent. Stock map dependencies are generated from traces; a map's own pack lands after its declared needs. A community map downloaded from a server is not in those stock map dependencies: it can refer to textures from any stock map's shared or map pack or the extras pack. Its server can supply its own pk3s, but does not guarantee stock dependencies.

The split builder previously discarded the entire nexcompat input, so its textures and scripts could never arrive through the split set. The builder now retains them; scripts go in core so the initial shader scan can see them, and remaining files go to extras. This affects newly built data releases only, not published archives. The split has no texture-to-pack index or community-map dependency manifest. A missing texture therefore cannot currently identify the required pack for priority fetching.

The engine caches successful external skinframes, including generated notexture when fallback is requested. fs_mountpack adds a search path but does not reload skinframes or reconstruct materials. Q3 shader scripts are parsed separately, and a material may have been built from a missing shader, so merely retrying a skinframe is insufficient. Server downloads can also continue after map loading (cl_joinbeforedownloadsfinish). These paths make late arrivals a plausible cause, not proof of the screenshot's cause.

Phone repacking converts DDS to ASTC KTX where beneficial and keeps DDS otherwise; it does not generate ETC2. The engine's KTX loader requires ASTC support and otherwise tries DDS; when repacking replaced rather than retained DDS, a device without ASTC cannot fall back to that removed file. The engine enables software DDS decoding without S3TC and disables runtime gl_texturecompression there. Xonotic enables r_texture_dds_load; a local override could change it. No dds_preserve handling was found in the phone repacker. Actual profile, GPU extensions and installed pack contents are needed to determine whether format support contributed.

Still required: publish a corrected indexed data set; map missing material/image names to all candidate packs, request them through the existing consent-aware downloader, handle late server and app mounts, rebuild affected materials as well as skinframes, and use a neutral fallback. Verify with an actual community map, missing shader and texture, late pack mounting, offline/metered states and non-ASTC GLES2. This change alone does not fix the reported rendering.
